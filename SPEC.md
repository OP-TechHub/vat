# VAT Input Claims Register — specification

A web app for tracking which input VAT invoices in the ledger have been claimed on monthly VAT returns (Sri Lanka, tax year April to March). It replaces an Excel workbook. `reference/prototype.html` is a working single-page prototype: its parsing, matching and report logic is the source of truth for behaviour.

## Stack
- Next.js (App Router, TypeScript), deployed on Vercel
- Supabase: Postgres, Auth (email + password), row level security
- Tailwind CSS; SheetJS (`xlsx`) for reading uploads and writing exports/templates in the browser

## Data (see `supabase/migrations/0001_init.sql`)
| Table / view | Purpose |
|---|---|
| `companies`, `company_members`, `company_member_permissions` | Each client company; users get a role per company (admin or member) and, as members, permissions per tab |
| `ledger_invoices` | Input invoices as per the ledger VAT control account |
| `schedule_lines` | Local input schedule submitted to IRD, per return month |
| `vat_returns` | One row of return figures per month |
| `invoice_claim_status` (view) | Ledger invoices with derived `claim_status`, `claim_month`, `auto_claim_month` |
| `schedule_line_match` (view) | Schedule lines with the matching ledger invoice number, if any |
| `export_sales` | Export sales report lines with customs details, per sales-report month (migration 0004) |
| `return_documents` | Filed return, IRD acknowledgement and credit voucher documents per period, stored in the `vat-claims` bucket (migrations 0005, 0007) |
| `customs_entries`, `import_purchases` | Customs declaration (CusDec) lines for both directions, one per item (migration 0011), the import ones being the Import Register; import purchase rows (migration 0008, no longer shown) |
| `replace_customs_entries`, `apply_customs`, `replace_import_month` (RPC) | Store customs entries and fill the matching reconciliation rows; replace a month of import purchases |
| `ird_status` | Credit voucher status, date and value per period (migration 0007) |
| `replace_ledger_month`, `replace_schedule_month`, `replace_export_month` (RPC) | Atomic replace of one month on upload |

`supabase/seed.sql` loads Oceanpick's 2026/27 data: 608 ledger invoices (Apr–Aug 2026), 244 schedule lines, the April return.

## Core rule: claim status
- An invoice is **Claimed** when its External Document No. equals a Tax Invoice No on any month's schedule, compared after trimming, upper-casing and removing whitespace. The claimed month is that schedule's return month (earliest if several).
- Manual override per invoice: a specific claimed month, or force "Not claimed". Auto applies when neither is set.
- Status is always derived (the view), never stored.

## Modules (migrations 0023, 0024)
After sign-in the top level is **Registers | VAT | TIEP**; each opens its own tabs. A module shows when it is switched on for the company (`company_modules`, Members › Modules) and the user may view at least one of its tabs. VAT tabs live under `/vat/…` (old paths redirect).

**Registers** is the one place the source registers are uploaded (tax-year selector in the header):
- **Import Register** (`reg_imports`): import CusDecs, the same `customs_entries` lines VAT › Import Register shows. VAT › Import Register no longer uploads; it links here.
- **Export Register** (`reg_exports`): the Business Central export sales line list (`sales_invoices` + `sales_invoice_lines`, `upload_sales_invoices`), grouped by invoice; plus the export CusDecs (`customs_entries`, direction export). Charge lines (BC line Type other than Item, service codes SE…, or freight / insurance / charges in the description) are flagged and left out of FOB; the flag can be corrected per line (`set_sales_line_charge`). Each export invoice adds its row to Export reconciliation in its invoice month (amount FC = FOB FC, net sales = FOB LKR, ex. rate = FOB LKR / FOB FC) and the customs columns fill from its CusDec (`apply_customs`). A row the register added (`from_register`) follows later uploads; a row from the old monthly sales report keeps its figures and is only linked (`sales_invoice_id`). Export reconciliation has no upload of its own.
- **Local Sales Register** (`reg_local`): the BC local sales line list, same tables with type Local; amounts are LKR.
- Re-uploading an invoice updates it (blank header fields keep what is held, lines are replaced by line number) and needs delete as well as upload. Pounds are converted to kg at 0.454 (original kept in qty_in / uom_in).
- Customs entries may be uploaded, edited and given documents with the permission of either the Registers tab or the VAT tab of their direction (`customs_perm`).

**TIEP Import Register** (migration 0025; logic in `lib/tiep/model.ts`, ported from the TIEP app):
- Import lines = every import customs entry (CusDec item) of the Import Register, plus TIEP fields in `tiep_import_ext` (material group, feed type, cancellation required Yes / Confirm / No, details pending, logbook duty total, remarks, legacy IMP id). TIEP rows refer to a line by (CusDec no., invoice no., item no.), because re-uploading a CusDec re-creates its lines; rows whose line has gone are flagged at the top of every TIEP page. A line without TIEP fields takes its group from classified lines with the same HS code (marked *), and "cancellation required" defaults to No for non-S CusDecs, Confirm for Equipment & Spares, else Yes.
- Per line: duties suspended = CID / PAL / SSCL coded 0 (else the logbook duty total); VAT deferred = VAT coded 2; cancelled = Completed postings, planned = Planned postings; left = qty − cancelled; balance = left − planned; outstanding = suspended × left / qty; due = CusDec date + cancellation period (Settings, default 365 days); overdue when left > 0 after the due date (as at today or the Settings as-at date). Status in order: Not applicable, Details pending, Over-cancelled, Fully cancelled, Over-planned, Fully planned, Partially cancelled, Partly planned, Open. FIFO numbers TIEP lines oldest first within each group. Financial year April–March.
- **Summary**: tiles, totals (imported / cancelled / outstanding / planned / pending confirmation / balance, with CID, PAL, SSCL, duty, VAT; optional estimated split for logbook lines), by material group (expandable), by financial year.
- **Import Register**: filters, sortable table, CSV; a line opens a dialog to set group, feed type, cancellation required and remarks, see its postings, or edit the import details (`tiep_save_import_line`, which writes the customs entry too). Add import line creates a customs entry by hand.
- **TIEP Status › Post cancellation**: export or local; qty = export qty × ratio (overwritable); FIFO over open lines of the product and unit, or one line; preview; `tiep_post_cancellation` re-checks every balance under a per-company lock and writes all rows in one transaction (refs CN-0001 / LS-0001, or the batch's ref).
- **Cancellation Ledger**: every posting row; Update (status, remarks, export CusDec / cancellation entry and date for the whole ref, `tiep_update_ref`) and Reverse (whole ref or one row, `tiep_reverse`). Logbook rows cannot be changed.
- **Settings**: conversion standards (yields, materials with annual ↔ per 1,000 kg linked through the edible fish basis, MUD lines; add / edit / delete; overlaps and gaps flagged; first vs last compared), TIEP item master (system items mapped to TIEP items, per-standard alternatives, confirmation per item no., bulk map, CSV / Excel import, CSV export; TIEP items edited across all standards), General (cancellation period, as-at date, bank guarantee).
- Permissions: read with view on any TIEP tab (`tiep_view`) and the module switched on; register edits need TIEP Import Register edit, postings TIEP Status edit, ledger changes Cancellation Ledger edit / delete, settings TIEP Settings edit / delete (`tiep_can`). TIEP viewers can read the import customs entries.
- **Exports / Local Sales Register** (migration 0026; `lib/tiep/invoices.ts`): the Registers' sales invoices of that type, each calculated per line from the standard for its date and the item master (whole fish = qty ÷ yield, materials = whole fish × per kg; charge lines left out; statuses OK, Excluded, Item not mapped, Not in standard, No standard, No date, No quantity). TIEP fields per invoice in `tiep_invoice_ext` (export E no., yield overrides, packing-list header and rows, documents, group). Commercial invoice / packing list PDFs are read (`lib/tiep/packingList.ts`) and attached to the invoice of the same number, filling in what was missing; an invoice not in the register can be added from the PDF with Registers upload permission. Local invoices are grouped into one MUD.
- **MUD** (`tiep_muds`, one per invoice or group): claims from the standard's MUD lines (or defaults) on the whole fish / boxes, rounded up to whole units; each claim proposed FIFO from open TIEP lines of its group (and feed type / keyword), never from lines imported after the invoice date; edits are kept as a pending allocation; the yield can be overridden per invoice. Every invoice without a saved MUD gets FIFO proposals, oldest first (shown as Pending confirmation on import lines). Save (`tiep_save_mud`, refs MUD-<invoice>) reserves Planned postings after checking balances; Withdraw releases them; Record customs cancellation (`tiep_record_writeoff`) posts the write-off figures Completed. The form prints from the browser (Print / Save as PDF) in the Sri Lanka Customs layout, with MUD form settings in `tiep_settings.mud_config`; unconfirmed item mappings print NOT CONFIRMED.
- **TIEP Status**: By customs entry and By cancellation entry matrices (products as columns or rows, quantities or outstanding LKR, CSV); Post cancellation; Local sales batches (`tiep_save_batch` copies the batch's customs entry, date and status to its postings); Logbook check against `tiep_logbook_summary`.
- **Settings** also: Confirm export mapping, Item mapping vs MUD (with MUD lines on file, `tiep_mudhist`), Documents (`tiep_documents`, files under `<company>/tiep/documents/`).
- Still to come (phase 5): moving the TIEP app's data (import line fields, cancellations and logbook history, batches, standards, item master, invoices and MUDs, MUD lines, documents and their files, logbook) and the reconciliation report.

## Screens
1. **Sign in**, then a company switcher (only companies the user belongs to) and a tax-year selector (e.g. 2026/27 = Apr 2026 to Mar 2027).
2. **Summary**
   - Tiles: ledger input VAT, claimed, not claimed, unclaimed with original invoice held (amount and count each).
   - Month-wise by posting date: invoices, total, claimed count/amount, unclaimed count/amount, originals held.
   - VAT return against ledger, per return month: schedule lines, schedule VAT total, local purchases tax per return, ledger balance posted, claimed from ledger, schedule VAT not in ledger.
   - Matrix: posting month by claimed month, with Not claimed and Total columns.
3. **Invoice listing**
   - Table: invoice no., posting date, vendor, external doc. no., description, amount, original VAT invoice (Yes / No / not marked, editable inline), status pill, claimed month (Auto / manual month / manual not claimed, editable inline).
   - Filters: posting month, status, original invoice, text search. Count and total of the filtered rows.
   - Upload a month: pick month + file, show a preview (rows found, total, rows skipped, rows that will be replaced), then confirm. Only rows posted in the chosen month are taken. Duplicate invoice numbers in a file are summed. Original-invoice marks and overrides survive a re-upload.
   - Download template button beside the file chooser.
4. **IRD input schedule**
   - Month selector; table of lines with a "Ledger invoice" column (matched invoice no. or "Not in ledger list"); totals.
   - Two manual columns per line, editable inline by editors and admins: "Ledger availability" (None by default until someone sets it, Available in ledger, Not available in ledger) and "Ledger reference" (free text). Stored on `schedule_lines`, included in the Excel export, and preserved on re-upload by tax invoice number.
   - Upload a month (same preview-then-confirm flow) and Download template. If the file has a Month column with several months, keep only the chosen month's rows. If VAT Amount is blank, use 18% of the value.
4a. **Export reconciliation** (table `export_sales`, one row per export invoice per sales-report month)
   - Column groups as in the Excel sheet. Details in sales report: Invoice No, Month, Amount FC (FOB) USD / EUR, Ex.rate, Net Sales (A). As per customs: Cusdec No, Date, Month, Currency Type (USD / EUR), Ex. Rate Custom LKR, Invoice Value as Per USD / EUR, Custom Value. Differences: Exchange Difference (1) = Custom Value − Net Sales (derived, never stored), Short Shipment (3), Sales Reversed in the Month (4), Updated in Custom Report.
   - Upload a sales-report month (same preview-then-confirm flow, Download template). Only the sales-report columns are required; customs and difference columns are taken if present. Re-upload keeps customs details already entered by invoice number where the file is blank.
   - Editors fill in or correct the customs and difference columns inline. Custom Value is recalculated as invoice value × customs rate whenever either changes.
   - View from / to month selectors show any range within the tax year, with a subtotal row per month (amount FC, net sales, customs value, exchange difference, short shipment, sales reversed) and a grand total when more than one month is shown.
   - Included in the Excel export as the "Export Reconciliation" sheet.
   - Upload CusDec PDFs (editors): ASYCUDA goods declaration printouts are read in the browser (`lib/pdfText.ts`, `lib/cusdec.ts`); fields are located by box label (customs reference and date, box 22 currency / amount, box 23 rate, consignee or exporter, invoice number always from box 44: its "INV NO:" line if there is one, else the reference under A.D.; blank, with a warning, when the box is empty or unreadable; nothing is taken from elsewhere on the form), then one line per item from page 1 and every continuation sheet: box 32 item no, box 33 HS code, description, box 41 UOM and quantity, box 46 statistical value and the item's tax table (CID, PAL, SSL, VTD / VAT: base, amount, MP code); the "Summary of Taxes" block is skipped. Lines are reviewed, the invoice number may be corrected, and they are saved as customs entries (re-uploading a CusDec replaces its lines); each PDF is kept in the `vat-claims` bucket and referenced from the entry (`doc_path`, migration 0010). A trailing "CusDec" column on both reconciliation tables, in the icon format of the Return filing page, opens the file and lets editors upload / replace / remove it per entry. Scanned bundles (invoice, packing list, CusDec... in one PDF, with a scanner’s word-level text layer or none) are handled by `lib/cusdecRead.ts`: the CusDec pages are located by heading (`cusdecPageGroups`), each declaration (main page plus continuation sheets) is parsed on its own, and those pages are OCR-read in two Tesseract modes (3 and 11) whose fields are merged; a file without text gets a shrunken quick OCR pass to find the pages. Tax amounts are checked against base × rate and replaced when OCR garbled them (noted on the row); an unreadable box 46 falls back to the CID tax base; landscape page images are rotated to whichever turn reads as words; headings match with one-letter OCR slips. The review table’s boxes are all editable for PDF rows. Scanned PDFs (no text layer) go through OCR (`lib/ocr.ts`: page image extracted with pdf.js, read with Tesseract, words grouped into positioned runs) and the same parser with looser tolerances; such rows are marked, and invoice value × rate is cross-checked against the statistical value.
   - Upload export customs entries (editors): CusDec lines stored in `customs_entries` (direction export, keyed by CusDec and invoice number). On save, and again whenever a month's sales report is uploaded, the "As per customs" columns of the sales row with the same invoice number (compared like document numbers) are filled from the latest entry: CusDec no, date, month, currency, customs rate, invoice value, customs value.
4b. **Import Register** (table `customs_entries`, direction import; migrations 0008–0011): a register of the import CusDecs themselves, with no purchase-ledger columns. One row per CusDec item (HS code line) under the month of its CusDec date, for any range of months in the tax year (entries whose date cannot be read are listed last). Column groups: Declaration (Cusdec No, Date, Month, Invoice No, repeated on every item line of a multi-item CusDec), Item (item no, HS code, description, supplier, UOM, quantity), Values (currency, customs rate, invoice value, customs value = the item's box 46 statistical value), Taxes as per customs (CID, PAL, SSCL amounts each with its MP code; Value for VAT = the VAT line's tax base, CIF plus duties; VAT amount, type VTD / VAT and code), and the CusDec document column (Open / Upload / Replace / Remove, shared by the lines of one declaration). Month subtotals and a grand total of customs value, CID, PAL, SSCL, value for VAT and VAT. Entries are added by uploading CusDec PDFs (text or scanned) or a spreadsheet of entries, as on the export tab. Import entries may have a blank invoice number (logbook entries). "To complete" tag and Remarks (migration 0019): a spreadsheet's To Complete column (Yes) tags a declaration entered from a logbook rather than read from its CusDec; the first column shows the tag with what is still missing (CusDec file, invoice no, supplier, currency, rate, invoice value, duties, VAT, VAT type), editors clear or set it with Mark complete / Tag to complete, and the To complete filter takes yes / no. Uploading the real CusDec (not tagged) replaces a tagged entry with the same CusDec number and month even when the invoice number differs, keeping its documents. Both columns are in the Excel export. Included in the Excel export as "Import Register". The `import_purchases` table and its upload remain in the database and code but are not shown.
5. **VAT reconciliation**
   - "Upload VAT return data" panel (editors): the VAT Return_Upload workbook, every period in the file upserted into `vat_returns` (see Upload formats).
   - Left panel, per month: submission date; the VAT return and return acknowledgement documents (Uploaded / Not uploaded, Open, Upload / Replace / Remove); then every entered cage of the return in return order (A, 0, B/2, C/2A, 3, D, D1, E, E1; H, 4, 5, I, 6, J, K, J2, 8, 8A, 10; 11, 12, 15, 16, Q, R2, 17, 18) and the three ledger figures. Inputs show thousands separators.
   - Right panel, months as columns, numbers right aligned in whole rupees: the entered cages with calculated 7 (4+5+6), 9 (7−8), available (9+10), 13 (11+12), 14 (9+10−13); arithmetic checks cage 15 less (13−3−8A) and cage 18 less (16−17−15); exempt ratio test: 7 × E ÷ (D+E), cage 8 less computed, K × E ÷ (D+E), cage 8A less computed, implied rate K ÷ J; then return vs ledger for exports, local sales, imports; schedule VAT total vs local purchases tax; claimed from ledger invoices; then return vs the uploaded reconciliations: zero rated goods (D) less Export reconciliation net sales, imports value (H) less the Import Register total for the month (value for VAT per customs where read, else customs value), local purchases value (I) less IRD input schedule value of purchases, each shown with the reconciliation total. Differences under 1 rupee count as agreed; larger ones are highlighted.
5a. **Return filing** (register of every taxable period from Jan 2020 to the current month, newest first, not limited to the tax-year selector)
   - Columns: Period code (IRD YYQM, e.g. Aug 2026 = 2632), Taxable period, Submitted on (per IRD acknowledgement), Data uploaded (Yes/No), Return uploaded (Yes/No), Acknowledgement uploaded (Yes/No). Filter: all periods, or only those with something missing.
   - Data uploaded is Yes when a `vat_returns` row exists for the period (loaded from the workbook or entered on the VAT reconciliation tab).
   - Return uploaded / Acknowledgement uploaded are Yes when a document is held for the period in the private `vat-claims` storage bucket (table `return_documents`). Members can open a document through a signed link; editors upload, replace and remove. Storage policies mirror the company roles.
5b. **IRD status** (every taxable period from Jan 2020, newest first, same range and show filters as Return filing)
   - Columns: Period code, Taxable period, Deferred import VAT (cage 4 of the period's return), Refund due (cage 15), Net refund (cage 18 negated: refund due less credits and tax payable, highlighted when tax is payable), Status, Date of credit voucher, Value of credit voucher, Credit voucher attachment. Totals row for the amounts.
   - Status is one of Credit voucher received, Credit voucher pending, Information under submission, RMI Form Received (migration 0018), any status a company admin adds under Status options (`ird_status_options`, migration 0022: add, rename, and delete once no period uses it; the four built-in statuses are fixed), or not set; held in `ird_status` with the voucher date and value. Date, value and attachment are editable once the status is received. The voucher is a `return_documents` row of kind `credit_voucher` in the `vat-claims` bucket, with Open / Attach / Replace / Remove. Remarks (free text, migration 0021) and Last updated (latest change to the status row or the voucher file) follow; rows are listed last updated first, then newest period first, with an Order switch for newest period first only.
5c. **Schedule submissions** (table `schedule_submissions`, migration 0020; the "DVAT Plan" workbook): one row per period code, IRD YYQM with M = 0 for a quarter (1910 = Jan–Mar 2019, then monthly from 2011), newest first, not limited to the tax-year selector.
   - Columns: Selected (tick), Period code, Period, Deferred input VAT, Sch 1 Output, Sch 2 Input VAT (amount, or text such as "No local purchases"), Sch 3 Import VAT, Sch 4 Credit/Debit Notes, Sch 6 Article Export, Sch 7 Service Export, Schedules submitted, SVAT 06, RMI, Return availability, Cusdecs availability, Sch 6 CusDecs, CusDecs in register, Remarks. Statuses as pills (Submitted / Available / Received / Full green; Not Submitted / Not Available / No CusDecs red; Partial amber).
   - Worked out, never stored (`lib/submissions.ts`): Schedules submitted = Sch 1, 3, 4, 6, 7 marked Submitted plus Sch 2 when it has an amount, "n of 6"; Cusdecs availability = No Sch 6 Exports (Sch 6 CusDecs 0), No CusDecs (none in register), Full (all), Partial. Totals row "Periods submitted" as in the workbook (deferred VAT > 0, Sch 2 with an amount, each Sch submitted, SVAT 06 out of the periods where it applies, returns available, Full / Partial / None), following the filters. With the seed workbook: 84 periods, 72 / 0 / 55 / 83 / 6 / 62 / 0 of 84, SVAT 41 of 72, returns 70 of 84, 25 Full / 25 Partial / 12 None, 18 selected.
   - Upload the workbook (`parseSubmissions`): heading row with Period Code in the first 15 rows, columns by heading, code worked out from Month when blank, title / notes / totals rows passed over; every period in the file upserted, others kept; replacing held periods needs delete. Download Excel writes the shown periods in the same layout (with the worked-out columns and totals row), which uploads back unchanged; Download template is the empty workbook.
   - Edit (edit permission): drop-downs for the statuses, inputs for the numbers, Sch 2 and Remarks, Selected tick, Add next period (the month after the latest); Delete a period with delete permission. Show filter: all, selected, return not available, CusDecs partial or missing, SVAT 06 not submitted; column filters.
6. **Export to Excel**: Invoice Listing (with status and claim month), IRD Submitted Input, VAT Returns.
7. **Members** (admin only): invite by email, set role and per-tab permissions (V / U / E / D grid, presets), remove.
8. **Column filters** on the row tables (Invoice listing, IRD input schedule, Export reconciliation, Import Register, Return filing, IRD status): a filter box under every column heading (`components/ColumnFilters.tsx`); contains-match on text, comparisons and ranges on numbers, `blank` for empty cells, yes / no for Yes / No columns; boxes combine; totals follow the filtered rows; Clear button while any is set.
9. **Log** (admin only, migration 0015): every change to data, members and permissions, recorded by triggers into `change_sets` (one per action / transaction; the `apply_customs` refresh run straight after an edit joins that edit's set) and `change_log` (row key, row before and after). Lists when, who, tabs, type and a description (server label for uploads, documents, members and undo; otherwise row counts), with per-row details (field before → after), filters by tab / person / type / dates, and Undo: reverses every row of the set in reverse order, refused while any row differs from how the set left it (naming the later sets still in effect), or when a document it would restore has been purged. An undo is a set itself (undo_of / undone_by) and can be undone. Files are stored under unique names and never deleted by the app; a file no longer referenced is recorded in `archived_files` and purged 30 days later, and log entries after 5 years, by `change_log_housekeeping`, run from an admin's browser once per company per session.

## Upload formats (`templates/`)
- Ledger: sheet "Invoice Listing"; Invoice No. (or Document No.), Posting Date, Vendor Name, External Document No., Description, Amount (LCY), Source Currency Amount.
- Schedule: Month, Serial No, Invoice Date, Tax Invoice No, Supplier's TIN, Name of the Supplier, Description, Value of purchase, VAT Amount.
- Export sales report: Invoice No, Month, Amount FC (FOB) USD / EUR, Ex.rate, Net Sales (A), then optionally Cusdec No, Date, Month, Currency Type, Ex. Rate Custom LKR, Invoice Value as Per USD / EUR, Custom Value, Short Shipment (3), Sales Reversed in the Month (4), Updated in Custom Report. A group-heading row above the column headings and month subtotal rows are ignored.
- Sales line list (Registers › Export / Local Sales, BC): Document No. (or Invoice No), Posting Date, Item No. (No.) or Description, Quantity (or Net Wt; "lbs" in the heading or a LB unit converts to kg), and Amount / Amount (LCY); optionally Customer Name, Type (Item / G/L Account …), Unit of Measure, Unit Price, Currency Code, Exchange Rate, Export CusDec, Boxes, Gross, Market (Export / Local: other market's rows skipped). Header within the first 20 rows of any sheet; total rows skipped.
- Find the header row within the first 15 rows; match columns by heading text, not position. Accept Excel serial dates and dd.mm.yyyy / dd/mm/yyyy / yyyy-mm-dd text. Accept .xlsx, .xls, .csv.

## Permissions
- admin: everything on every tab, and manages members. member: access set per tab in `company_member_permissions` (migration 0014): no row = no access (tab hidden, data unreadable); a row = view, plus any of upload (first upload of a month or a document into an empty slot), edit (inline edits, rows by hand, return figures, IRD status, "Edit uploaded data") and delete (delete rows, replace / remove documents, re-upload data already held). Summary is view only; Return filing has no edit.
- Data belongs to tabs: ledger_invoices → Invoice listing, schedule_lines → IRD input schedule, export_sales and export customs entries → Export reconciliation, import_purchases and import customs entries → Import Register, vat_returns → VAT reconciliation (also readable with view on Return filing or IRD status), returns / acknowledgements → VAT reconciliation or Return filing, credit vouchers and ird_status → IRD status. Uploads go through `upload_*` functions that check upload (and delete when replacing).
- Enforced by RLS in the database; the UI only mirrors it. Never use the service-role key in the browser.

## Out of scope for v1
